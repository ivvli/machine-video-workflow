# 04 入库与调用规则

## A. 新视频入库

1. 建立 `视频分析/YYYY-MM-DD_账号_视频简称/` 证据文件夹。
2. 保存来源链接、发布日期、互动数据、时长和账号。
3. 完整播放或分析本地原视频，不能只看封面和卡片。
4. 补齐字幕、镜头节奏、产品证据、客户心理和CTA。
5. 标明证据等级：已验证、画面推断、待确认。
6. 分析完成后，只在 [01 视频样本索引](./01_视频样本索引.md) 增加一行。

## B. 写新文案时的调用顺序

1. **确认目标客户：** 谁会买这台机器。
2. **选择一个客户问题：** 从 [03 客户问题库](./03_客户问题与反对意见.md) 选一个主问题。
3. **检查素材证据：** 现有画面能证明哪些说法。
4. **检索完整样本：** 从 [01 视频样本索引](./01_视频样本索引.md) 找同买家问题或同心理机制的完整分析，优先读取其 `framework.md`。
5. **拆三条链：** 明确对标视频的文案功能链、观众心理链和证据链，不能只摘几句原文。
6. **提取框架：** 删除原作者表达、产品名、型号和无证据承诺，只保留可迁移的说服机制。
7. **填写适配卡：** 把我方唯一卖点、传统预期、真实反转、物理证明、具体商业价值和CTA回报逐位置填入。
8. **按四大铁律原创：** 单点爆破、夸张情绪钩子、立预期并打预期给具体爽感、低风险精准引流。
9. **独立审稿：** 检查心理推进、信息增量、证据、事实边界、原创表达和历史差异；失败则回到适配卡重写。
10. **朗读和计时：** 检查承接、口语、夸张语气是否自然，以及实际配音时长。
11. **建立声画表：** 每个重要结论必须有对应证据镜头或已确认事实。
12. **用户确认并锁定：** 文案单独确认后才生成逐镜脚本。
13. **发布后回收：** 播放、完播、评论、私信和客户问题回填到档案。

## C. 每条记录的最低字段

| 类别 | 必填内容 |
|---|---|
| 身份 | 平台、账号、链接、日期、时长 |
| 数据 | 播放、点赞、评论、收藏/转发（页面可见时） |
| 文案 | 页面标题、口播/字幕、前三秒钩子、CTA |
| 镜头 | 逐段画面、人物动作、机器动作、成品动作 |
| 客户 | 目标客户、具体痛点、反对意见、咨询回报 |
| 证据 | 哪句话被哪个画面证明，哪些说法仍待测试 |
| 复用 | 可借结构、不可照搬内容、适合的产品类型 |

## D. 数据库整洁规则

- 总入口永远只有本文件夹的 `README.md`。
- 样本索引不写长分析，只保存一行摘要和完整档案链接。
- 文案策略不按账号重复记录，出现新规律才新增。
- 客户问题按购买阶段归类，不按视频逐条堆放。
- 原始证据不复制到本文件夹，避免多个版本互相冲突。
- 旧分析文件不删除、不覆盖；后续版本在原证据文件夹内更新。
